## 一、先理解"为什么需要这些层"

想象你要拍一部电影：

| 角色           | 对应 Cocos 模块                  | 做什么                           |
| -------------- | -------------------------------- | -------------------------------- |
| **导演**       | Director                         | 决定每帧拍什么、什么时候拍       |
| **摄影师**     | Camera                           | 决定从哪个角度看、视野多大       |
| **灯光师**     | Light                            | 打光                             |
| **道具组**     | Scene（场景里的 Node/Component） | 准备好所有要拍的东西             |
| **摄影机硬件** | GFX                              | 底层硬件，真正把光变成图像的东西 |
| **后期制作**   | Post Processing                  | 加滤镜、特效                     |

## 二、GFX：摄影机硬件层

GFX 就是一台**摄影机的硬件抽象**。不管你用的是索尼、佳能还是RED摄影机（对应 WebGL、Vulkan、Metal），GFX 给你一个统一的操作界面。

### 核心概念用"画画"来理解

**1. Device（画板）**

> 你画画需要一块画板。Device 就是这块画板，所有东西都在上面创建。

**2. CommandBuffer（绘画指令清单）**

> 你不是直接在画布上画，而是先写一张"指令清单"：
>
> - 第一步：把背景涂成蓝色
> - 第二步：在中间画一个圆
> - 第三步：给圆涂上红色
>
> 写完清单后，一次性交给画师（GPU）去执行。为什么？因为**跟 GPU 说话很慢**，不如攒一堆话一次说完。

```
你（CPU）写指令清单          GPU 执行指令
┌─────────────────┐        ┌─────────────────┐
│ begin()         │        │                 │
│ 清屏为蓝色       │  ───►  │ 🎨 执行！        │
│ 画圆             │        │                 │
│ 涂红色           │        └─────────────────┘
│ end()           │
└─────────────────┘
```

**3. Buffer（颜料桶）**

> Buffer 就是装数据的"桶"。有三种桶：
>
> - **顶点桶**：装模型形状数据（三角形的三个顶点坐标）
> - **索引桶**：装"用哪些顶点"的索引（第1、3、5号顶点组成一个面）
> - **Uniform 桶**：装"全局参数"（比如相机位置、光照颜色，每个顶点都用同一份）

**4. Texture（贴纸/照片）**

> Texture 就是一张贴纸或照片。模型表面要画什么图案？就用 Texture 贴上去。

**5. Shader（绘画技法/配方）**

> Shader 是一段告诉 GPU "每个像素怎么上色"的配方。比如：
>
> - 顶点 Shader：把 3D 坐标变成 2D 屏幕坐标
> - 片段 Shader：算出每个像素应该是什么颜色

**6. Pipeline State（绘画全套工具箱）**

> 画一幅画需要同时决定：用什么笔、什么颜料、要不要透视、要不要混合颜色……Pipeline State 把这些**所有状态打包成一个整体**。换一种画法 = 换一个 Pipeline State。

**7. Descriptor Set（颜料盘）**

> 画画时，你需要把颜料桶（Buffer）和贴纸（Texture）摆放在颜料盘上，Shader 才知道去哪里取。Descriptor Set 就是这个颜料盘，它把资源和 Shader 绑定在一起。

**8. RenderPass + Framebuffer（画框+画布）**

> RenderPass 定义"这幅画要画几层、每层画完要不要保留"
> Framebuffer 定义"画在哪块画布上"
>
> 比如画阴影：先在一张小画布上画深度图（阴影贴图），然后在主画布上画场景时参考这张深度图。

## 三、Rendering：拍摄流程层

如果 GFX 是摄影机硬件，那 Rendering 就是**整个拍摄流程的组织方式**。

### 三层架构 = 三级导演

```
┌──────────────────────────────────────┐
│  RenderPipeline（总导演）              │
│  "今天拍这部戏，需要3个拍摄流程"        │
│                                       │
│  ┌────────────────────────────────┐   │
│  │  RenderFlow（流程导演）          │   │
│  │  "先拍阴影，再拍主画面"          │   │
│  │                                 │   │
│  │  ┌──────────────────────────┐   │   │
│  │  │  RenderStage（场景导演）   │   │   │
│  │  │  "这个镜头先画不透明的，    │   │   │
│  │  │   再画半透明的"            │   │   │
│  │  └──────────────────────────┘   │   │
│  └────────────────────────────────┘   │
└──────────────────────────────────────┘
```

### 一帧画面的完整流程

```
游戏每帧（1/60秒）
│
├── 1. Director.tick() — 导演喊"开拍！"
│
├── 2. 组件 update() — 所有角色更新位置/状态
│
├── 3. Root.frameMove() — 开始渲染
│   │
│   ├── 4. 对每个 Camera：
│   │   │
│   │   ├── 场景剔除（看不见的就不画了）
│   │   │   ├── 视锥剔除：画面外的 → 丢掉
│   │   │   ├── 遮挡剔除：被挡住的 → 丢掉
│   │   │   └── 距离剔除：太远的 → 丢掉
│   │   │
│   │   ├── 5. Pipeline.render(cameras)
│   │   │   │
│   │   │   ├── ShadowFlow（拍阴影）
│   │   │   │   └── ShadowStage：从光源角度画一张深度图
│   │   │   │
│   │   │   ├── ForwardFlow（拍主画面）
│   │   │   │   └── ForwardStage：
│   │   │   │       ├── 不透明物体（近→远，先画近的减少重复绘制）
│   │   │   │       └── 透明物体（远→近，先画远的保证混合正确）
│   │   │   │
│   │   │   └── PostProcessFlow（后期制作）
│   │   │       ├── Bloom（辉光）
│   │   │       ├── FXAA（抗锯齿）
│   │   │       └── ColorGrading（调色）
│   │   │
│   │   └── 6. GFX 执行 CommandBuffer → GPU 画出来
│   │
│   └── 7. present() — 显示到屏幕上
│
└── 完成！等下一帧
```

## 四、Render Graph：智能拍摄计划系统 ⭐ 新架构

### 1. 传统管线 vs Render Graph：手动 vs 智能

**传统管线（Pipeline-Flow-Stage）** 就像**手动安排拍摄计划**：

```
导演手动安排：
1. 先拍阴影场景（ShadowFlow）
   └─ 从光源角度拍一张深度图（ShadowStage）
2. 再拍主画面（ForwardFlow）
   └─ 先拍不透明物体，再拍透明物体（ForwardStage）
3. 最后做后期（PostProcessFlow）
   └─ 加滤镜、特效（PostProcessStage）

问题：
❌ 导演需要手动管理所有道具（资源）
❌ 道具什么时候创建、什么时候销毁，全靠经验
❌ 容易忘记销毁 → 内存泄漏
❌ 拍摄顺序固定，难以优化
```

**Render Graph** 就像**AI 智能拍摄计划系统**：

```
AI 自动安排：
1. 你只需要告诉系统："我要拍这个场景"
2. 系统自动分析：
   ✓ 需要哪些道具（资源）
   ✓ 道具什么时候创建、什么时候销毁
   ✓ 哪些镜头可以合并拍摄
   ✓ 怎么安排拍摄顺序最高效
3. 自动生成最优拍摄计划并执行

优势：
✅ 道具自动管理，不会忘记销毁
✅ 拍摄计划自动优化
✅ 内存使用更高效
✅ 性能更好
```

### 2. 用"拍电影"理解 Render Graph 的核心概念

#### **Render Graph（拍摄计划图）**

> 想象你要拍一部电影，所有场景、镜头、道具之间的关系，画成一张**流程图**：
>
> ```
> 场景A（阴影） → 场景B（主画面） → 场景C（后期）
>     ↓                  ↓
> 道具1（深度图）    道具2（颜色图）
> ```
>
> 这就是 Render Graph！它用**图结构**（有向无环图 DAG）组织整个拍摄流程。

#### **Resource Graph（道具管理系统）**

> 传统方式：导演需要手动记录：
> - "道具A在第3场戏用完，可以销毁"
> - "道具B在第5场戏才用，现在不用创建"
>
> Render Graph：系统自动管理！
> - **自动创建**：道具第一次被需要时，自动创建
> - **自动销毁**：道具最后一次使用后，自动销毁
> - **自动复用**：两个道具如果使用时间不重叠，可以共享同一块内存（资源别名优化）

#### **Compiler（拍摄计划优化器）**

> 就像 AI 剪辑师，会自动优化你的拍摄计划：
>
> **优化1：合并镜头**
> ```
> 原计划：
> 镜头1：拍背景（需要道具A）
> 镜头2：拍前景（需要道具A）
> 
> 优化后：
> 合并镜头：一次拍完背景+前景（道具A只准备一次）
> ```
>
> **优化2：资源别名**
> ```
> 原计划：
> 道具A（第1-3场戏用）→ 占用100MB
> 道具B（第4-6场戏用）→ 占用100MB
> 总共：200MB
> 
> 优化后：
> 道具A和B时间不重叠 → 共享同一块100MB内存
> 总共：100MB（省一半！）
> ```

#### **Executor（拍摄执行器）**

> 优化好的拍摄计划，交给执行器去执行：
> - 准备道具（分配资源）
> - 按计划拍摄（执行渲染命令）
> - 用完的道具及时归还（释放资源）

### 3. Render Graph 的完整流程

```
用户代码（你写的）
    ↓
"我要拍一个场景，需要这些镜头"
    ↓
┌─────────────────────────────────────────┐
│  1. 构建 Render Graph（画拍摄计划图）     │
│     - 添加通道（RasterPass、ComputePass）│
│     - 声明资源（纹理、缓冲）              │
│     - 建立依赖关系（A → B）               │
└─────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────┐
│  2. Compiler 编译（AI 优化拍摄计划）      │
│     - 分析资源使用情况                    │
│     - 合并可以合并的通道                  │
│     - 资源别名优化（省内存）              │
│     - 生成最优执行计划                    │
└─────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────┐
│  3. Executor 执行（按计划拍摄）           │
│     - 自动创建需要的资源                  │
│     - 执行渲染命令                        │
│     - 自动销毁不用的资源                  │
└─────────────────────────────────────────┘
    ↓
最终画面呈现到屏幕
```

### 4. 实际例子：用 Render Graph 画一帧

```typescript
// 传统方式（手动管理）
class TraditionalPipeline {
    render() {
        // 手动创建资源
        const shadowMap = createTexture(1024, 1024);  // 需要记住创建
        const colorBuffer = createTexture(1920, 1080);
        const depthBuffer = createTexture(1920, 1080);
        
        // 手动安排流程
        renderShadow(shadowMap);      // 拍阴影
        renderScene(colorBuffer, depthBuffer, shadowMap);  // 拍主画面
        postProcess(colorBuffer);     // 做后期
        
        // 手动销毁（容易忘记！）
        destroyTexture(shadowMap);    // 忘了销毁 → 内存泄漏
        destroyTexture(colorBuffer);
        destroyTexture(depthBuffer);
    }
}

// Render Graph 方式（自动管理）
class RenderGraphPipeline {
    render(ppl: BasicPipeline) {
        // 1. 声明资源（系统自动管理生命周期）
        ppl.addRenderTarget('ShadowMap', Format.R32F, 1024, 1024);
        ppl.addRenderTarget('ColorBuffer', Format.RGBA8, 1920, 1080);
        ppl.addDepthStencil('DepthBuffer', Format.DEPTH, 1920, 1080);
        
        // 2. 添加通道（系统自动优化）
        // 阴影通道
        const shadowPass = ppl.addRenderPass(width, height, 'ShadowPass');
        shadowPass.addRenderTarget('ShadowMap', LoadOp.CLEAR, StoreOp.STORE, Color.BLACK);
        shadowPass.addDepthStencil('DepthBuffer', LoadOp.CLEAR, StoreOp.DISCARD, 1.0, 0, ClearFlagBit.DEPTH_STENCIL);

        // 主画面通道
        const mainPass = ppl.addRenderPass(width, height, 'MainPass');
        mainPass.addRenderTarget('ColorBuffer', LoadOp.CLEAR, StoreOp.STORE, Color.BLACK);
        mainPass.addDepthStencil('DepthBuffer', LoadOp.CLEAR, StoreOp.DISCARD, 1.0, 0, ClearFlagBit.DEPTH_STENCIL);

        // 后期通道
        const postPass = ppl.addRenderPass(width, height, 'PostProcess');
        postPass.addRenderTarget('OutputColor', LoadOp.CLEAR, StoreOp.STORE, Color.BLACK);
        
        // 3. 系统自动：
        // ✓ 分析资源依赖
        // ✓ 优化渲染流程
        // ✓ 自动创建和销毁资源
        // ✓ 不会内存泄漏
    }
}
```

### 5. Render Graph 的三大核心优势

#### **优势1：自动资源管理（最大亮点）**

> **传统方式**：像手动记账，容易忘记销毁资源 → 内存泄漏
> 
> **Render Graph**：像智能管家，自动管理资源生命周期
> - 第一次使用时自动创建
> - 最后一次使用后自动销毁
> - 不重叠的资源共享内存（资源别名）

#### **优势2：全局优化**

> **传统方式**：优化空间有限，只能局部优化
> 
> **Render Graph**：编译器看到整个渲染流程，可以全局优化
> - 合并通道
> - 优化资源分配
> - 减少状态切换

#### **优势3：现代化设计**

> **传统方式**：设计较早，不完全契合现代图形 API（Vulkan/WebGPU）
> 
> **Render Graph**：专为现代图形 API 设计
> - 完美契合 Vulkan/WebGPU 的资源管理模型
> - 更好地利用现代硬件特性
> - 跨平台统一接口

### 6. 什么时候用 Render Graph？

| 场景 | 推荐使用 |
|------|---------|
| **新项目** | ✅ Render Graph（面向未来） |
| **复杂渲染流程** | ✅ Render Graph（自动优化） |
| **需要高性能** | ✅ Render Graph（内存优化） |
| **简单项目** | ⚠️ 传统管线（学习成本低） |
| **老项目迁移** | ⚠️ 需要评估成本 |

## 五、关键概念通俗解释

### 1. 为什么需要"场景剔除"？

> 想象你站在一个房间里，面朝一堵墙。你身后有100件家具，但你只能看到面前的墙。如果 GPU 把身后100件家具都画一遍，那就是**99% 的工作白做了**。所以渲染前先"剔除"看不到的东西。

### 2. 为什么不透明物体"近→远"画，透明物体"远→近"画？

> **不透明物体近→远**：先画近的，远处的被挡住的部分就不会被画了（Early-Z 测试），省性能。
>
> **透明物体远→近**：玻璃杯后面的东西要先画好，再画玻璃杯，才能正确地"透过去看到后面"。如果先画玻璃杯，GPU 不知道后面有什么，就没法做透明混合。

### 3. 什么是 UBO（Uniform Buffer Object）？

> 就是**所有角色共享的公告板**。比如"太阳在哪里"这个信息，每个像素都需要知道，但数据只有一份。UBO 就是这块公告板，GPU 的每个线程都能读取。

### 4. 什么是 Descriptor Set？

> Shader 是配方，但它不知道"第1号颜料桶里装的是什么颜色"。Descriptor Set 就是**配方的配料表**，告诉 Shader："0号桶是相机矩阵，1号桶是光照数据，2号贴纸是纹理"。

### 5. 前向渲染 vs 延迟渲染

> **前向渲染**（Cocos 默认）：每个物体，算一次光照，画一次。物体多、光源多时，计算量 = 物体数 × 光源数。
>
> **延迟渲染**：先画一遍所有物体的"属性"（位置、法线、颜色）到几张图上（G-Buffer），然后对每个像素只算一次光照。计算量 = 像素数 × 光源数，光源多时更高效。

## 六、一句话总结

**GFX 是"画笔和画布"的抽象**，让你不用关心底层是 WebGL 还是 Vulkan；**Rendering 是"画画流程"的组织**，决定先画什么后画什么、怎么剔除、怎么排序；**Render Graph 是"智能拍摄计划系统"**，自动管理资源、优化流程，让渲染更高效、更现代化。三者配合，每帧 1/60 秒内把 3D 世界变成你屏幕上的 2D 图像。
