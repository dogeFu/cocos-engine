# Bullet 物理引擎移除方案

> **优先级**: 5.5 (插入在Physics和3D之间) | **预计时间**: 2-3天 | **风险等级**: ⭐⭐⭐ 中高

---

## 一、模块概述

### 1.1 功能描述

Bullet是Cocos引擎中的**C++原生物理引擎后端**之一（通过WASM/ASM.js实现），提供：

- **完整的3D刚体动力学** (基于Bullet Physics SDK)
- **复杂碰撞形状** (Box, Sphere, Capsule, Cylinder, Cone, Plane, Mesh, Terrain等)
- **约束系统** (P2P, Hinge, Fixed, Configurable)
- **角色控制器** (Character Controller: Box/Capsule)
- **高级特性**:
  - BVH (Bounding Volume Hierarchy) 三角网格加速
  - 碰撞缓存和接触数据管理
  - 高级碰撞过滤
  - 地形碰撞专用优化

### 1.3 移除理由

根据你的最新指示：**"不要用C++的物理引擎，后续游戏需要自己接入，我们不再维护了"**

具体原因：
- ✅ **Bullet是C++原生实现**，维护成本极高
- ✅ **代码量巨大**: ~197,000行TypeScript + 对应的C++代码
- ✅ **不再需要官方物理支持**: 游戏项目将自行集成第三方库（如Matter.js, Planck.js）
- ✅ **减少构建复杂性**: 不再需要编译链接Bullet SDK
- ✅ **符合轻量化目标**: 删除最大的物理后端
- ✅ **与整体策略一致**: Physics模块整体删除，Bullet作为其中一部分也应删除

## 三、依赖关系分析

### 3.1 被谁引用？

```typescript
// 1. cocos/physics/framework/physics-selector.ts
//    物理后端选择器会引用所有后端
import { BulletWorld } from '../bullet/bullet-world';
import { BulletInstance } from '../bullet/instantiate';

// 2. cocos/physics/physx/instantiate.jsb.ts
//    可能与Bullet有交互（后端切换逻辑）

// 3. exports/physics-bullet.ts
export * from '../cocos/physics/bullet'; // 或类似导出
```

### 3.2 Bullet自身依赖

```typescript
// bullet内部依赖:
import { Vec3, Mat4, Quat } from '../../core/math';  // 数学库
import { IPhysicsWorld } from '../spec/i-physics-world'; // 接口规范
import { BulletPhysicsConfig } from './bullet-env';     // 配置

// Bullet可能还依赖:
// - native C++ Bullet SDK (通过JSB绑定)
// - Bullet-specific data structures
```

### 3.3 影响范围评估

- **直接影响**:
  - `physics-selector.ts` - 需要移除Bullet选项
  - `exports/physics-bullet.ts` - 需要删除
  - 物理后端注册逻辑

- **间接影响**:
  - 使用Bullet作为物理后端的项目将无法编译
  - 但由于我们整体删除Physics模块，这是预期行为

- **编译影响**:
  - TypeScript层: 需要清理Bullet相关import
  - 原生层: 如果有Bullet C++绑定，也需要清理
