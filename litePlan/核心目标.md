# 精简cocos-engine

面向AI\休闲游戏的轻量引擎

---

## 一、核心原则

### 1. AI友好原则

- **代码可读性优先**：删除过度抽象的代码，保持逻辑清晰
- **API简洁明了**：减少装饰器使用，降低AI理解成本
- **文档驱动开发**：每个保留模块必须有清晰的文档和示例
- **训练数据友好**：保留的代码风格应接近主流框架（如Three.js）

### 2. 轻量化原则

- **专注休闲游戏**：不追求3A游戏能力，只保留2D/轻量3D功能
- **单平台优先**：优先保证Web平台稳定，原生平台按需适配
- **依赖最小化**：删除不必要的第三方库，减少打包体积

### 3. 渐进式裁剪原则

- **大模块优先**：按大模块裁剪，小模块暂不重构，确保稳定性
- **单步验证**：每次只裁剪一个模块，必须编译通过+单元测试通过
- **可回滚机制**：每次裁剪前创建Git分支，失败可快速回滚
- **文档同步更新**：裁剪的同时更新API文档和示例代码

### 4. 向后兼容原则

- **保留核心API**：游戏开发常用API保持不变
- **删除的模块不保证兼容性**：删除的功能暂时不提供代替方案，直接删除

## 三、模块依赖分析

### 1. TypeScript层依赖关系

```
Game (游戏入口)
 ├─ Core (核心基础)
 ├─ Scene Graph (场景树)
 │   ├─ Core
 │   └─ Animation
 ├─ Rendering (渲染管线)
 │   ├─ GFX
 │   ├─ Scene Graph
 │   └─ Render Graph ❌ (待删除)
 ├─ Asset (资源管理)
 │   ├─ Core
 │   └─ Scene Graph
 ├─ 2D (2D渲染)
 │   ├─ Scene Graph
 │   ├─ Rendering
 │   └─ UI
 ├─ 3D (3D渲染)
 │   ├─ Scene Graph
 │   ├─ Rendering
 │   └─ Physics ❌
 ├─ Physics ❌ (待删除)
 │   ├─ Scene Graph
 │   └─ Core
 ├─ Input (输入系统)
 │   └─ Core
 ├─ Audio (音频系统)
 │   ├─ Core
 │   └─ Asset
 └─ UI (用户界面)
     ├─ 2D
     └─ Scene Graph
```

### 2. C++层依赖关系

```
cocos/bindings (JSB绑定层)
 ├─ cocos/core (核心C++实现)
 ├─ cocos/renderer (渲染器C++实现)
 │   ├─ gfx (GFX C++实现)
 │   └─ pipeline (管线C++实现)
 ├─ cocos/physics (物理C++实现) ❌
 └─ cocos/audio (音频C++实现)
```

### 3. 构建系统依赖

**CMake构建流程**：

```
CMakeLists.txt (根配置)
 ├─ native/cocos/CMakeLists.txt (引擎核心)
 │   ├─ core/ (核心模块)
 │   ├─ renderer/ (渲染模块)
 │   ├─ physics/ (物理模块) ❌
 │   └─ audio/ (音频模块)
 ├─ native/tools/ (构建工具)
 └─ third-party/ (第三方库)
     ├─ SpiderMonkey (JS引擎)
     ├─ OpenGL ES (图形API)
     ├─ Bullet/Ammo (物理引擎) ❌
     └─ ... (其他库)
```

### 4. 小游戏平台依赖

**影响小游戏构建的模块**：

- ✅ **保留**：Core、GFX、Scene Graph、2D、Input、Audio、Asset
- ⚠️ **简化**：Rendering（删除Render Graph）、Animation（删除Marionette）
- ❌ **删除**：Physics、Terrain、Render Graph、Profiler

## 四、裁剪策略

### 1. 完全删除的模块

| 模块             | 代码量  | 删除理由                               | 影响范围               |
| ---------------- | ------- | -------------------------------------- | ---------------------- |
| **Render Graph** | ~2万行  | 休闲游戏不需要定制化渲染管线           | Rendering模块          |
| **Physics**      | ~3万行  | 休闲游戏物理需求简单，可用第三方库替代 | 3D模块、Scene Graph    |
| **3D**           | ~5万行  | 专注2D游戏，保留基础3D能力即可         | Scene Graph、Rendering |
| **Terrain**      | ~1万行  | 休闲游戏很少用地形系统                 | 无依赖                 |
| **Profiler**     | ~5000行 | 可用浏览器DevTools替代                 | 无依赖                 |

**删除步骤**：

1. 删除TypeScript代码（`cocos/render-graph/`, `cocos/physics/`, `cocos/3d/`等）
2. 删除C++代码（`native/cocos/render-graph/`, `native/cocos/physics/`等）
3. 删除第三方库（Ammo.js、Bullet等）
4. 更新构建配置（CMakeLists.txt、tsconfig.json）
5. 修复编译错误（删除相关import）
6. 运行单元测试，修复失败用例

---

### 2. 大幅简化的模块

#### 2.1 Animation模块（简化70%）

**保留功能**：

- ✅ Spine动画支持
- ✅ DragonBones动画支持
- ✅ Tween补间动画
- ✅ 基础骨骼动画

**删除功能**：

- ❌ Marionette动画系统（复杂状态机）
- ❌ 动画混合树
- ❌ IK/FK系统
- ❌ 动画重定向

**代码量**：~1.5万行 → ~5000行

---

#### 2.2 Rendering模块（简化50%）

**保留功能**：

- ✅ 传统渲染管线（Pipeline → Flow → Stage）
- ✅ 基础光照和阴影
- ✅ 后处理效果（可选）

**删除功能**：

- ❌ Render Graph系统
- ❌ 高级渲染特性（体积光、屏幕空间反射等）
- ❌ 多渲染目标优化

**代码量**：~3万行 → ~1.5万行

---

#### 2.3 Asset模块（简化40%）

**保留功能**：

- ✅ 基础资源加载（图片、音频、JSON等）
- ✅ Bundle系统
- ✅ 资源缓存

**删除功能**：

- ❌ 复杂依赖管理
- ❌ 资源热更新（简化版）
- ❌ 原生平台特殊加载逻辑

**代码量**：~1万行 → ~6000行

---

### 3. 保留模块，第一期不优化

| 模块            | 优化方向                   | 预期效果    |
| --------------- | -------------------------- | ----------- |

## 六、风险评估

### 1. 技术风险

| 风险               | 影响                     | 概率 | 应对方案                        |
| ------------------ | ------------------------ | ---- | ------------------------------- |
| **模块依赖复杂**   | 删除模块导致编译失败     | 高   | 使用依赖分析工具，逐步删除      |
| **C++/TS同步问题** | 双版本维护困难           | 高   | 优先删除C++代码，TS代码独立维护 |
| **小游戏平台适配** | 删除模块影响小游戏构建   | 中   | 保留小游戏必需模块              |
| **性能下降**       | 删除优化代码导致性能下降 | 低   | 保留核心优化，性能测试验证      |
| **API不兼容**      | 删除API导致项目无法运行  | 中   | 提供迁移指南和polyfill          |

---

### 2. 项目风险

| 风险         | 影响               | 概率 | 应对方案                         |
| ------------ | ------------------ | ---- | -------------------------------- |
| **时间超期** | 项目延期           | 中   | 采用敏捷开发，分阶段交付         |
| **人力不足** | 开发进度慢         | 中   | 优先删除高价值模块，其他模块按需 |
| **社区反对** | 删除功能引起不满   | 低   | 提供替代方案，保留核心功能       |
| **文档缺失** | 用户不知道如何使用 | 中   | 同步编写文档和示例               |

---

### 3. AI友好性风险

| 风险               | 影响                  | 概率 | 应对方案                             |
| ------------------ | --------------------- | ---- | ------------------------------------ |
| **AI训练数据不足** | AI无法理解裁剪后的API | 低   | 提供丰富示例，补充训练数据           |
| **API设计不合理**  | AI生成代码质量差      | 中   | 参考Three.js API设计                 |
| **文档不清晰**     | AI无法正确使用API     | 中   | 编写AI友好的文档（结构化、示例丰富） |
