> **优先级**: 3 (调整后) | **预计时间**: 2-4小时 | **风险等级**: ⭐ 极低
>
> **版本**: v2.0 (修正版) | **修正日期**: 2026-04-11
>
> **重要说明**: 本方案基于实际代码审查修正，修复了v1.0中的重大错误

## 一、模块概述

### 1.1 功能描述

XR（Extended Reality，扩展现实）模块提供VR/AR/MR相关的功能支持：

```
cocos/xr/ 模块结构：

├── index.ts              # 模块入口 (25行)
├── xr-enums.ts           # XR枚举定义 (124行)
└── event/
    └── xr-event-handle.ts # XR事件处理 (123行)
```

**实际总规模**: 3个TypeScript文件，**272行代码**（⚠️ v1.0错误地估计为4,200-4,500行！）

**主要功能**：
- VR/AR设备检测和初始化
- XR事件系统（UI交互事件：hover、click、keyboard input）
- XR枚举常量定义（XREye、XRPoseType等）
- WebXR渲染循环集成

### 1.2 移除理由

根据你的指示：**"现在没有人做这个了"**

具体原因：
- ✅ **VR/AR游戏市场小**：休闲游戏几乎不涉及XR功能
- ✅ **代码无用武之地**：没有项目使用XR模块
- ✅ **减少维护负担**：虽然代码量小，但也是要维护的
- ✅ **符合轻量化目标**：删除所有不必要的功能
- ✅ **降低复杂度**：少一个模块就少一份文档和测试负担

**✅ 重要发现：所有UI组件的XR代码都有 `if (USE_XR)` 保护**

这意味着：
- UI组件中的XR代码是**条件编译代码**
- 当 `USE_XR = false` 时，这些代码不会执行
- 删除XR模块后，这些if块变成**死代码**

#### 导出文件（1个）

```typescript
// 7. exports/xr.ts - 导出文件（需要删除）
export * from '../cocos/xr';
```

### 3.2 UI组件引用XR的原因（已确认）

**实际情况**（非推测）：

UI组件引用XR是为了支持 **VR模式下的交互适配**：

```typescript
// slider.ts 的实际代码示例（第197-223行）
if (USE_XR) {
    node.on(XrUIPressEventType.XRUI_HOVER_STAY, self._xrHoverStay, self);
    node.on(XrUIPressEventType.XRUI_CLICK, self._xrClick, self);
    node.on(XrUIPressEventType.XRUI_UNCLICK, self._xrUnClick, self);
}

// 对应的事件处理方法（第344-379行）
protected _xrHandleProgress (point: Vec3): void {
    if (!USE_XR) return;  // ← 安全守卫
}
protected _xrClick (event: XrUIPressEvent): void {
    if (!USE_XR) return;  // ← 安全守卫
    this._xrHandleProgress(event.hitPoint);
}
```

**处理策略**（见第五章）：
- **选项A（推荐）**: 只删除import，保留死代码（USE_XR永远为false）
- **选项B**: 删除import + 清理所有XR相关死代码

### 3.3 影响范围评估

- **直接影响**: **6个源文件** + **1个导出文件** + **2个配置文件** = **9个文件**
- **间接影响**:
  - 使用XR功能的VR/AR项目将无法编译（但你说没人做）
  - UI组件中的XR代码变成死代码（不影响运行时）
- **编译影响**: 仅TypeScript层
- **运行时影响**:
  - ❌ XR功能完全消失
  - ✅ 所有其他功能不受影响（UI等只是多了些不可达的死代码）
